# Brightpeer – rules for every agent and tool

- WHOLE SITE FROZEN (owner, 26.11.2026: "Verbessere Admin und lasse alles funktionieren, dann friere die Seite ein"): the state after the commit "Admin: To-do-Liste …; Anmeldung: bestehende E-Mail" is the approved version. Change NOTHING on Brightpeer – no code, design, text, translation, layout, price, e-mail, database or setting – unless the owner explicitly asks for that specific change in the current request. No clean-ups, refactors, "improvements" or follow-up fixes on your own. If a requested change would touch other parts, ask first.
- Never delete owner-requested features or data while doing another task or resolving merge conflicts.
- Admin area (26.11.2026): every tab shows a green counter of open items and the overview starts with a "To do" list (`adminTodo`, `todoBox` in js/app.js): expert applications, interviews, field tests, new requests, hours, unpaid prepayments, payouts, referral bonuses. On phones the tabs are one scrollable row.
- Admin simpler (26.11.2026, "Mach Admin verständlicher und einfacher"): the admin area is in German (hard-coded, only the owner uses it); the 15 tabs sit in 5 area buttons (`ADMIN_GROUPS`: Heute zu tun, Fachleute, Firmen & Aufträge, Geld, Statistik & Einstellungen) with sub-tabs; every tab starts with a "what is this / So geht's" box (`ADMIN_HELP`); buttons are bigger and the main action is green (`btn-accent`). Tab keys and links stay the same.
- Visitors (26.11.2026): the owner's own visits never count, also logged out – a device where she was once signed in as admin is remembered (`bp_owner` in localStorage, `isOwnerDevice`).
- Sign-up (26.11.2026): an e-mail that already has an account gets no e-mail from the auth service, so the form shows "This email already has a Brightpeer account" with Log in / Forgot password instead of "check your email"; companies see their own confirmation text (no CV).
